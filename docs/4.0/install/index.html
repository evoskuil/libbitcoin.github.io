    Install

    bs is a single executable. Prebuilt binaries are not yet published, so installing means building the five libraries and the server from source. Three install scripts in the server repository do this end to end, including the dependencies, on Linux and macOS. Windows builds with Visual Studio.

    Requirements

    Requirement Version
    C++ compiler C++20: GCC 13 or later, Clang 16 or later, Xcode, or Visual Studio 2026
    Boost 1.86.0 or later
    libsecp256k1 0.8.0, the bitcoin-core repository, with the ellswift, recovery and schnorrsig modules
    CMake 3.30 or later, for the CMake builds only
    Autotools autoconf, automake, libtool and pkg-config, for the GNU build only
    git to fetch the repositories

    Optionally UltrafastSecp256k1 for GPU batch signature verification, and OpenSSL for TLS, which is on by default.

    On Ubuntu 24.04:

    sudo apt install build-essential git autoconf automake libtool pkg-config cmake

    Linux and macOS

    Each script clones the dependencies it is asked to build, then clones and builds libbitcoin-system, libbitcoin-database, libbitcoin-network, libbitcoin-node and libbitcoin-server in that order, runs the server tests, and installs. Repositories are cloned shallow at the master branch unless --build-full-repositories is given. Options the script does not recognize are passed through to every dependency's configure step, which is how CPU feature flags are set.

    GNU Autotools

    git clone https://github.com/libbitcoin/libbitcoin-server
cd libbitcoin-server
./builds/gnu/install-gnu.sh --prefix=$HOME/libbitcoin --build-boost --build-secp256k1 --build-config=release --build-link=static --build-post-install-clean

    The binary is $HOME/libbitcoin/bin/bs. Without --prefix it installs to /usr/local.

    Option Effect
    --prefix=<path> Installation destination. Default /usr/local.
    --build-config=<mode> release or debug.
    --build-link=<mode> static or dynamic.
    --build-boost Build Boost 1.86.0 from source rather than using the system's.
    --build-secp256k1 Build libsecp256k1 v0.8.0 from source.
    --build-ultrafast Build UltrafastSecp256k1.
    --build-parallel=<n> Parallel jobs. Default is the hardware thread count.
    --build-src-dir=<path> Where sources are cloned. Default is the current directory.
    --build-obj-dir=<path> Intermediate objects. Default obj.
    --build-use-local-src Reuse sources already present instead of cloning.
    --build-full-repositories Full clones instead of shallow single-branch clones.
    --build-post-install-clean Remove dependency sources and objects after install.
    --build-skip-tests Do not build or run tests.
    --noninteractive Take defaults at every prompt.
    --verbose Show script output.

    CMake

    ./builds/cmake/install-cmake.sh --prefix=$HOME/libbitcoin --build-boost --build-secp256k1 --build-config=release --build-link=static

    Takes the same options as the GNU script, and additionally captures -DCMAKE_PREFIX_PATH, -DCMAKE_INSTALL_PREFIX, -DCMAKE_INCLUDE_PATH and -DCMAKE_LIBRARY_PATH for the CMake configure step. libsecp256k1 is built with CMake here rather than Autotools. Feature options take the CMake form, for example -Denable-avx2=ON.

    CMake presets

    ./builds/cmake/install-presets.sh --build-preset=nix-gnu-release-static --build-boost --build-secp256k1

    The preset fixes configuration and link mode, so there is no --prefix, --build-config or --build-link. Objects go to obj/<preset> and the install goes to prefix/<preset> under the source directory, so the binary is ./prefix/nix-gnu-release-static/bin/bs.

    Preset Configuration
    nix-gnu-release-static release, static, -O3
    nix-gnu-release-shared release, shared, -O3
    nix-gnu-debug-static debug, static, -Og -g1 --coverage
    nix-gnu-debug-shared debug, shared, -Og -g1 --coverage

    CPU features

    Hashing has hand-written paths for Intel SHA-NI, SSE4.1, AVX2 and AVX-512, and for ARM NEON and SVE. Which paths are compiled is a build decision. Which path runs is decided at runtime by CPUID on Intel and by the operating system's feature query on ARM, so a binary built with every path enabled runs correctly on a machine that lacks some of them.

    GNU option CMake option Compiler flags
    --enable-shani -Denable-shani=ON -msse4 -msha
    --enable-sse41 -Denable-sse41=ON -msse4.1
    --enable-avx2 -Denable-avx2=ON -mavx -mavx2
    --enable-avx512 -Denable-avx512=ON -mavx512f -mavx512bw
    --with-ultrafast -Dwith-ultrafast=ON GPU batch verification

    All are off by default. The ARM paths have no option and are compiled whenever the target is ARM.

    Windows

    The solution is builds/msvc/vs2026/libbitcoin-server.sln, platform toolset v145, with StaticDebug and StaticRelease configurations for x64, Win32, ARM64 and ARM. Dependencies come from NuGet packages declared in each project's packages.config: libbitcoin-boost and its component packages at 1.91.0, secp256k1_vc145 at 0.8.0, and UltrafastSecp256k1-vc145. The sibling libbitcoin repositories are referenced by relative path through the .import.props sheets, so they must be checked out beside libbitcoin-server.

    The scripted build:

    .\builds\msvc\build-msvc.cmd --build-config StaticRelease --build-platform x64 --build-version vs2026 --enable-shani

    Output lands under bin\<platform>\<Debug|Release>\v145\static\bs.exe. The --build-symbols option selects default, disabled or public-only debug symbols.

    Docker

    libbitcoin-build ships a two-stage Alpine image that builds bs statically and copies only the binary and a startup script into the runtime stage. It exposes 8333 for peers and the service ports, and mounts /bitcoin/blockchain for the store and /bitcoin/conf for configuration.

    docker compose --env-file bs-linux.env --file bs-linux.yml up -t 3600 -d

    The long stop timeout matters. bs flushes the store on close and a SIGKILL corrupts it. Never down -v, which deletes the store volume.

    Continuous integration

    Every push builds the GNU, CMake, presets and MSVC paths across Ubuntu 24.04 with GCC 12 through 16 and Clang 18 and 19, macOS with Apple Clang, and Windows with Visual Studio 2026, in debug and release, static and dynamic. One GCC debug leg collects coverage.

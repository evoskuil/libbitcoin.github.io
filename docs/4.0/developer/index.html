    Developer

    The five libraries are C++20, each in its own repository, each depending only on the libraries below it. All are at version 4.0.0. This section is for building against them: which header to include, what to link, the conventions every declaration follows, and the entry points of each library.

    Including

    Each library has one aggregate header. Include it and nothing else from that library.

    Library Header Namespace Export macro
    system <bitcoin/system.hpp> libbitcoin::system BC_API
    database <bitcoin/database.hpp> libbitcoin::database BCD_API
    network <bitcoin/network.hpp> libbitcoin::network BCT_API
    node <bitcoin/node.hpp> libbitcoin::node BCN_API
    server <bitcoin/server.hpp> libbitcoin::server BCS_API

    The aggregate headers say so themselves: API users include only this header, and direct use of other headers is fragile and unsupported. Each aggregate includes the one below it, so <bitcoin/node.hpp> brings system, database and network with it. namespace bc = libbitcoin is defined for brevity.

    Linking

    On Linux and macOS the libraries install as libbitcoin-system, libbitcoin-database, libbitcoin-network, libbitcoin-node and libbitcoin-server, each with a pkg-config file whose Requires line chains to the libraries below it, so pkg-config --libs libbitcoin-node resolves the whole stack down to libsecp256k1 and Boost.

    On Windows the libraries are not packages. Each repository's solution imports its siblings' .import.props sheets by relative path, so the five repositories are cloned side by side and built in dependency order. The property sheets define BC_STATIC or BC_DLL according to the linkage and add the sibling include and library directories.

    Conventions

    Every declaration follows these, and code built against the libraries reads best when it does too.

    • NOEXCEPT on nearly every function. It expands to noexcept in release builds and to nothing in debug builds, so debug builds propagate assertion diagnostics. Functions that may throw, such as configuration parsing, are marked THROWS.
    • code is std::error_code in every library, and each library registers its own error category with its own error_t enumeration. Network additionally translates Boost error codes from ASIO, Beast, SSL, WebSocket, JSON and RPC into its own category.
    • cptr is std::shared_ptr<const T>, the handle for immutable values such as blocks, headers, transactions and messages. ptr is std::shared_ptr<T>, the handle for polymorphic services such as sessions, channels, protocols and the node.
    • Copy and move are declared by macro at the top of each class: DEFAULT_COPY_MOVE_DESTRUCT for value types, DELETE_COPY_MOVE_DESTRUCT or DELETE_COPY_MOVE for owners of resources or threads. The _DESTRUCT variants add a virtual defaulted destructor.
    • BC_ASSERT is a debug-only assertion. INLINE forces inlining on MSVC.
    • Handlers are moved in as rvalue references, result_handler&&, and invoked on a strand. Bind a member function with BIND, post it with POST, or run it on the pool with PARALLEL.

    Libraries

    • system. Chain types, script machine, hashing, wallet primitives, serialization and configuration parsing.
    • database. The memory-mapped store and the query interface over it.
    • network. The proactor, sessions, channels, protocols and messages.
    • node. full_node, its configuration, the chasers and the chase event bus.
    • server. server_node, the parser, service sessions, interface declarations and dispatch.
    • Test. How the libraries are tested, and how to test code built on them.
